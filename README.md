Телеграм-бот для школьного класса на **Python + aiogram 3**. Класс один раз настраивает расписание уроков и время звонков, а дальше бот сам напоминает о домашних заданиях и уроках на завтра — прямо в чат.

---

## ✨ Возможности

| | |
|---|---|
| 🚀 **Онбординг** | Пошаговая настройка: количество уроков, время звонков, расписание на каждый день недели (с опциональной субботой). Повторная настройка уже настроенного чата требует явного подтверждения и сохраняется одной атомарной транзакцией |
| 📚 **Сегодня** | Сводка на день: уроки сегодня, домашка к сдаче, просроченные задания |
| 📅 **Расписание** | Просмотр расписания по дням недели с указанием времени уроков |
| 🗓 **Изменения по датам** | Разовые изменения школьного расписания на конкретную дату поверх недельного шаблона: отмена урока (показывается зачёркнутым), замена предмета, изменение времени, добавление разового урока, а также свободный день / праздник / каникулы / дистанционный день с примечанием. Шаблон при этом не меняется; перед сохранением показывается «сейчас → станет», удаление/очистка — с подтверждением. Итоговое расписание учитывается в «Сегодня» и в напоминаниях (в группе — только администраторам) |
| 🔀 **Чётная/нечётная неделя** | Чередование недель A (нечётная) и B (чётная). Неделя определяется не по номеру недели года, а по опорной дате-понедельнику (началу недели A), которая хранится в настройках чата. Обычное расписание можно скопировать в недели A и B и затем отредактировать различия; в редакторе видно, какая неделя правится. «Сегодня», расписание на завтра и напоминания автоматически выбирают нужную неделю. По умолчанию все чаты используют одно расписание (`all`) и работают без повторного онбординга. Изменения по датам имеют приоритет над недельным шаблоном (в группе — только администраторам) |
| 📝 **Домашние задания** | Добавление, редактирование и отметка о выполнении домашки по предметам и датам, архив выполненного, подтверждение перед безвозвратным удалением |
| 🎯 **Доп. занятия** | Кружки, репетиторы, секции и дополнительные уроки (например, английский в 18:00) — отдельно от школьных уроков. Еженедельные и разовые, с названием, временем (`18:00` или `18:00 - 19:00`), местом и примечанием. Просмотр доступен всем, изменение в группе — только администраторам. Показываются отдельным блоком в «Сегодня», в расписании выбранного дня и в напоминании на завтра |
| ⏰ **Напоминания** | Отдельный экран (кнопка «⏰ Напоминания» или `/settings` → «⏰ Напоминания»): пять независимо настраиваемых категорий: ДЗ на завтра, портфель на завтра, ДЗ в день сдачи (утром), изменения/отмены завтрашних уроков и напоминания о доп. занятиях (у каждого занятия — свой «за N минут», 0–10080). Есть «тихие часы»: несрочные уведомления откладываются, но напоминание о занятии не приходит после его начала. Доставка идемпотентна (outbox с атомарным захватом), переживает перезапуск, безопасна при двух копиях бота, обрабатывает Telegram RetryAfter/Forbidden, старые задания периодически очищаются |
| 🌍 **Часовой пояс каждого чата** | У каждого чата свой часовой пояс (IANA, например `Europe/Kyiv`). От него зависят **все** пользовательские даты и время: «Сегодня», сроки сдачи ДЗ, чётные/нечётные недели, изменения по датам, доп. занятия и все напоминания — глобального часового пояса для пользовательских дат больше нет. Значение по умолчанию берётся из `TIMEZONE`, поэтому существующие чаты автоматически получают тот пояс, на котором и работали. Есть выбор популярных зон и ручной ввод; перед сохранением показывается текущее местное время. Неверная или устаревшая зона не останавливает планировщик — такой чат просто работает на поясе по умолчанию. Один проход планировщика корректно обслуживает чаты из разных поясов (у каждого своё «сегодня»/«завтра»), включая переходы летнего времени |
| 📎 **Фото и файлы в ДЗ** | К домашнему заданию можно приложить фотографию, документ или изображение как файл — до 5 вложений с необязательной подписью. Бот **не скачивает и не хранит сами файлы**: сохраняются только `file_id` / `file_unique_id` Telegram, тип, имя файла, размер и подпись. Ничего не распаковывается и не запускается, имя файла считается недоверенным (санитизируется и используется только для отображения). Вложения предлагаются сразу после описания в потоке добавления, добавляются и удаляются у существующего ДЗ (удаление — с подтверждением), а при открытии карточки присылаются вместе с ней. Если Telegram перестал принимать старую ссылку на файл, бот показывает понятное сообщение и предлагает приложить файл заново; одно «мёртвое» вложение не мешает отправке остальных. Удаление ДЗ каскадом удаляет его вложения |
| ✍️ **Авторство записей** | У домашних заданий, доп. занятий и изменений по датам сохраняется, кто их создал и кто изменил последним (Telegram-id и отображаемое имя) плюс время создания/изменения. В карточке ДЗ и доп. занятия автор виден сразу. Записи, созданные до появления авторства, честно помечаются как «Автор неизвестен» — авторство им не додумывается |
| 📜 **История изменений** | Журнал важных действий (⚙️ Настройки → «📜 История», в группе — только администраторам): кто и когда добавил, изменил, удалил, отметил выполненным или вернул запись. Постраничный просмотр с фильтром по типу событий. Удалённая запись исчезает, а безопасная строка аудита остаётся. В журнал не попадают токены, полные Telegram Update и лишние персональные данные — только id и имя автора, тип и id сущности, действие и короткое описание. Старые записи автоматически удаляются по настраиваемому сроку (`AUDIT_RETENTION_DAYS`, по умолчанию 180 дней) |
| ⚙️ **Настройки** | Общий экран (кнопка «⚙️ Настройки» или `/settings`): часовой пояс, режим прав на изменение ДЗ, история изменений, данные и резервная копия, полный сброс настроек. Управление уведомлениями вынесено на отдельный экран «⏰ Напоминания», чтобы разделы не дублировались |
| ⌨️ **Команды и календарь** | Быстрые команды `/today`, `/schedule`, `/homework`, `/extra`, `/settings`, `/help` (регистрируются в меню Telegram при запуске). При выборе даты сдачи ДЗ доступен компактный inline-календарь с листанием по месяцам, выделением текущего дня и запретом прошедших дат; ввод даты вручную (`ДД.ММ`) по-прежнему работает |
| 🛠 **Диагностика** | Команда `/status` (в группе — только администраторам) показывает версию приложения, состояние планировщика и время последнего тика, версию миграции БД и размер очереди напоминаний (ожидающие / в процессе / зависшие). Секреты (токен, `DATABASE_URL`, пути) не раскрываются |
| 💬 **Личка и группы** | Работает как в личном чате, так и в общем чате класса — настройки хранятся отдельно на каждый `chat_id`, с разграничением прав (см. ниже) |

Под капотом — конечный автомат (FSM) для диалогов с персистентным хранилищем состояния, автоматическое разбиение длинных сообщений на части (лимит Telegram в 4096 символов), HTML-форматирование с экранированием пользовательского ввода, единый сервис времени (часовой пояс каждого чата + корректная обработка переходов летнего времени) и планировщик задач на APScheduler с outbox-таблицей для надёжной доставки.

## 🔐 Права доступа

- **В личном чате** ограничений нет — единственный пользователь может делать всё.
- **В группе/супергруппе** только администраторы чата могут:
  - полностью сбрасывать данные (⚙️ Настройки → «Сбросить всё»);
  - менять расписание и время звонков (первичная настройка, переконфигурация, редактирование расписания);
  - вносить изменения по датам (отмены, замены, свободные дни, праздники и т. п.);
  - включать/выключать чередование недель и редактировать недели A/B;
  - менять настройки и время напоминаний;
  - смотреть историю изменений (⚙️ Настройки → «📜 История») и менять режим прав на ДЗ;
  - менять часовой пояс чата (в личном чате это делает сам пользователь).
- **Домашние задания**: *добавлять* ДЗ может любой участник при любом режиме — это совместный список класса. Кто может *изменять, отмечать выполненным и удалять* уже существующую запись, задаёт администратор в ⚙️ Настройках:
  - `collaborative` — **режим по умолчанию**, любой участник (полностью совпадает с прежним поведением, поэтому обновление ничего не ломает);
  - `creator_or_admin` — автор записи или администратор. У записей без автора (созданных до появления авторства) автора для сравнения нет, поэтому они остаются доступны всем — иначе класс потерял бы доступ к своим же старым записям; кому нужен строгий вариант, выбирает `admin_only`;
  - `admin_only` — только администраторы, включая записи без автора.

  Удаление ДЗ дополнительно требует подтверждения («Удалить безвозвратно?»), чтобы случайный тап не уничтожал запись без права на отмену.
- **Доп. занятия** может просматривать любой участник, но в группе/супергруппе добавлять, изменять и удалять их могут только администраторы; удаление также требует подтверждения. В личном чате ограничений нет.

При отказе бот показывает понятное сообщение («🚫 Это действие доступно только администраторам чата.», «🚫 Это ДЗ добавил другой участник…») вместо тихого игнорирования действия.

**Все проверки прав выполняются на серверной стороне.** Скрытая кнопка — только удобство: каждый изменяющий данные хендлер сам проверяет права перед обращением к БД (см. `services/permissions.py` и `middleware/access.py`), поэтому устаревшая или подделанная `callback_data`, равно как и подложенное FSM-состояние, будет отклонена. Право на редактирование ДЗ перепроверяется ещё раз в момент записи, а не только при открытии меню.

```
telegram-school-bot/
├── bot.py             # Точка входа: миграции, middleware, роутеры, планировщик

├── utils.py           # Разбиение сообщений, HTML-экранирование, safe-парсинг callback_data и др.
├── handlers/          # Обработчики диалогов и команд
│   ├── onboarding.py  #   первичная настройка/переконфигурация расписания
│   ├── today.py        #   сводка на сегодня
│   ├── schedule.py    #   просмотр и редактирование расписания
│   ├── date_overrides.py #   изменения по датам (отмены/замены/праздники/разовые уроки)
│   ├── homework.py    #   CRUD домашних заданий
│   ├── extra.py       #   CRUD доп. занятий (кружки/репетиторы/секции)
│   ├── settings.py    #   ⏰ Напоминания и ⚙️ Настройки (пояс, права, данные, сброс)

│   ├── status.py      #   /status — диагностика для администраторов
│   └── common.py      #   /start, /help, /cancel + команды разделов (/today, /schedule, …)
├── keyboards/         # Reply/inline клавиатуры
│   └── calendar.py    #   компактный inline-календарь выбора даты
├── middleware/
│   └── access.py      #   контекст чата, guard онбординга, проверка прав админа
├── database/          # SQLAlchemy-модели, async-доступ к БД, FSM-хранилище
│   ├── models.py      #   модели + constraints/индексы + авторство и audit_log
│   ├── db.py           #   CRUD, атомарный онбординг, outbox-джобы
│   ├── fsm_storage.py  #   персистентное FSM-хранилище на SQLite
│   └── migrate.py      #   применение Alembic-миграций и проверка ревизии
├── alembic/            # Версионируемые миграции схемы БД
├── services/
│   ├── effective_schedule.py #   единый расчёт итогового расписания (шаблон + изменения по датам + недели A/B)
│   ├── timeservice.py #   единый источник времени/дат: часовой пояс чата, DST, тихие часы
│   ├── audit.py       #   авторство и журнал изменений (безопасные краткие записи)
│   ├── attachments.py #   разбор и валидация вложений ДЗ (только ссылки Telegram)
│   ├── permissions.py #   политика прав на изменение ДЗ (проверка на сервере)
│   ├── status.py      #   сбор безопасной диагностики для /status
│   └── scheduler.py   #   напоминания (5 категорий) через APScheduler + идемпотентный outbox
└── tests/              # pytest + pytest-asyncio: БД, хендлеры, планировщик, права доступа
```

**Стек:** aiogram 3 (async), SQLAlchemy 2 + aiosqlite (async ORM над SQLite), Alembic (миграции), APScheduler, pytz, python-dotenv.

**Поддерживаемая БД:** только SQLite (`DATABASE_URL` обязан начинаться с `sqlite`) — это осознанное ограничение текущей версии, зафиксированное в `config.py`.

## ⚙️ Установка и запуск

### Локально

```bash
git clone https://github.com/blikzes-bit/telegram-school-bot.git
cd telegram-school-bot

uv sync --all-extras --dev    # окружение по pyproject.toml + uv.lock

cp .env.example .env          # укажи свой BOT_TOKEN

uv run alembic upgrade head   # поднять схему БД (отдельный шаг, см. ниже)
uv run python bot.py
```

Схему нужно поднять **до** первого запуска: `uv run alembic upgrade head`. Бот миграции не применяет — он лишь проверяет, что база на актуальной ревизии, и отказывается стартовать с понятной ошибкой, если это не так (см. раздел «Миграции БД» ниже).

### Docker

Готовый мультиархитектурный образ (`amd64` + `arm64`) публикуется в GHCR при каждом пуше в `main`. Не содержит тестов, dev-инструментов и Node, запускается от непривилегированного пользователя.

У образа **три роли**, задаются командой. Бот и API делят `database/models.py` и слой сервисов, поэтому едут одним тегом — так между ними не может возникнуть расхождения версий.

```bash
# 1. Накатить миграции и выйти. Отдельным шагом, а не побочным эффектом
#    старта бота, — после него бот и веб можно поднимать в любом порядке.
docker run --rm -v school_bot_data:/data \
  ghcr.io/blikzes-bit/telegram-school-bot:latest migrate

# 2. Бот
docker run -d --name school-bot \
  -e BOT_TOKEN=your_token_here \
  -e TIMEZONE=Europe/Kiev \
  -v school_bot_data:/data \
  --health-cmd "python -c \"import os,sys,time; p=os.environ['HEARTBEAT_FILE']; sys.exit(0 if os.path.exists(p) and time.time()-os.path.getmtime(p)<150 else 1)\"" \
  ghcr.io/blikzes-bit/telegram-school-bot:latest bot

# 3. Mini App: API и собранный фронтенд с одного origin
docker run -d --name school-web \
  -e BOT_TOKEN=your_token_here \
  -e APP_ENV=production \
  -e SESSION_SECRET=... \
  -v school_bot_data:/data -p 8000:8000 \
  --health-cmd "python -c \"import urllib.request,sys; sys.exit(0 if urllib.request.urlopen('http://localhost:8000/api/v1/health').status==200 else 1)\"" \
  ghcr.io/blikzes-bit/telegram-school-bot:latest web
```

`HEALTHCHECK` не зашит в образ намеренно: роли проверяются по-разному (бот обновляет `HEARTBEAT_FILE`, API отвечает на `/api/v1/health`), а директива статическая — поэтому проверка задаётся на контейнере.

За обратным прокси роли `web` нужен `FORWARDED_ALLOW_IPS` с адресом прокси, иначе ограничитель попыток входа увидит один и тот же IP у всех запросов и превратится в общий лимит на всех пользователей.

**`SESSION_SECRET` должен совпадать у бота и у веба.** Бот хеширует им одноразовый токен запуска, API по этому же хешу его ищет — если значения разойдутся, вход будет молча падать с «launch token is invalid».

База данных хранится в `/data/school_bot.db` — том нужен для сохранения данных между перезапусками контейнера.

### Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `BOT_TOKEN` | ✅ | — | Токен бота от [@BotFather](https://t.me/BotFather) |
| `TIMEZONE` | ❌ | `Europe/Kiev` | Часовой пояс **по умолчанию** для новых чатов (и запасной вариант, если у чата сохранён неизвестный пояс). Каждый чат может задать свой пояс в ⚙️ Настройках |
| `DATABASE_URL` | ❌ | `sqlite+aiosqlite:///school_bot.db` | Строка подключения к БД (только SQLite) |
| `FSM_STORAGE` | ❌ | `sqlite` | `sqlite` — персистентное хранилище состояний диалогов (переживает перезапуск), `memory` — только для локальной разработки |
| `HEARTBEAT_FILE` | ❌ | `.heartbeat` | Файл, который планировщик обновляет каждую минуту; по нему проверяется живость роли `bot` |
| `AUDIT_RETENTION_DAYS` | ❌ | `180` | Сколько дней хранится история изменений; старые записи удаляются ночным обслуживанием. `0` — не удалять никогда |

## 🌐 Веб-версия (Mini App)

Помимо бота есть защищённое **Telegram Mini App** — веб-интерфейс поверх той
же базы и той же доменной логики (расписание, доп. занятия). На первом этапе
он **только для чтения**: авторизация → выбор класса → экраны «Сегодня»,
«Расписание», «Домашние задания», «Доп. занятия». Подробности —
[`docs/WEB_APP_ARCHITECTURE.md`](docs/WEB_APP_ARCHITECTURE.md).

**Как открыть:** в чате класса выполните команду `/web` — бот проверит, что
вы участник группы, выдаст одноразовую ссылку и кнопку для запуска Mini App.
Открыть приложение для произвольного `chat_id` нельзя.

## 🗃️ Миграции БД

Схема версионируется через **Alembic** (`alembic/`) вместо ручных `ALTER TABLE`.

Применение миграций — **отдельный шаг**, а не побочный эффект старта бота. Так бот и веб-приложение можно поднимать в любом порядке, и видно, что миграция прошла, до того как что-то живое стартовало:

```bash
uv run alembic upgrade head                                   # из чекаута
docker run --rm -v <данные>:/data <образ> migrate             # в Docker
```

Бот при старте только сверяет ревизию базы с ожидаемой. Если база отстала, он не стартует и печатает, что именно не так и как это починить, — вместо невнятного «no such table» позже, посреди работы обработчика.

Для **существующей** продакшн-базы, созданной до внедрения Alembic (т.е. любой `school_bot.db`, работавший со старой версией бота), перед первым запуском новой версии один раз выполните:

```bash
alembic stamp e42f61dd6f2f   # baseline-ревизия, соответствующая старой схеме
alembic upgrade head          # применит constraints/индексы/outbox/FSM-таблицы
```

### Миграция group → supergroup

Когда Telegram обновляет обычную группу до супергруппы, chat_id меняется. Бот отслеживает системное сообщение об этом и переносит все данные на новый chat_id в одной транзакции — вручную ничего переносить не нужно. Переносится всё: расписание и звонки, недели A/B, домашние задания (вместе с авторством и вложениями), доп. занятия, изменения по датам, настройки напоминаний, часовой пояс, режим прав на ДЗ и журнал истории изменений.

## 🔄 Обновление, бэкап и диагностика

**Обновление существующей установки:**

```bash
git pull                       # забрать новую версию
docker compose up -d --build   # пересобрать и перезапустить (или перезапустить процесс)
```

Перед запуском новой версии примените миграции шагом `migrate` (см. «Миграции БД»). `.env` и `BOT_TOKEN` остаются прежними.

**Резервное копирование и восстановление** (в чате): «⚙️ Настройки» → «💾 Данные и резервная копия».
- 📦 JSON — полная копия чата (расписание, звонки, недели A/B, изменения по датам, доп. занятия, ДЗ, настройки, часовой пояс). Токен, содержимое файлов и FSM в копию не попадают; для вложений сохраняются только `file_id` + метаданные (Telegram не гарантирует их вечную переносимость между ботами).
- 📊 CSV — расписание для Excel/Google Таблиц; 📅 ICS — уроки/занятия/сроки ДЗ в календарь.
- Импорт JSON — только для админа группы, режимы `merge`/`replace` (для `replace` — двойное подтверждение), одной транзакцией с откатом при ошибке; целевой чат всегда текущий.

**Диагностика:** команда `/status` (в группе — только админам) показывает версию приложения, состояние планировщика, время последнего тика, версию миграции БД и размер очереди напоминаний. Секреты не раскрываются.

**Troubleshooting:**

| Симптом | Что проверить |
| --- | --- |
| Бот не отвечает после `git pull` | Логи старта: применились ли миграции; корректен ли `BOT_TOKEN` в `.env` |
| Не приходят напоминания | `/status` — планировщик «работает» и свежий «последний тик»; часовой пояс чата в «⚙️ Настройки»; тихие часы |
| Docker `HEALTHCHECK` красный | Обновляется ли `HEARTBEAT_FILE` (планировщик тикает раз в минуту) |
| Зависла форма (FSM) | Отправить `/start` или «❌ Отмена» — состояние сбросится |
| «Кнопка устарела» | Открыть раздел заново: старые callback-кнопки безопасно отклоняются |

## 🧪 Тесты и качество кода

```bash
uv run pytest                              # полный набор тестов
uv run pytest --cov=. --cov-report=term-missing  # с покрытием
uv run ruff check .                        # линт
uv run mypy .                              # проверка типов
uv audit --frozen --no-dev                 # аудит зависимостей на уязвимости
```

Тесты покрывают: часовой пояс каждого чата (Europe/Kyiv, UTC, America/New_York, разные календарные даты у чатов в один и тот же момент, переходы летнего времени — несуществующее и повторяющееся локальное время, отсутствие двойного напоминания, неизвестная зона не ломает планировщик), вложения ДЗ (FSM добавления, несколько файлов, лимит и дубликаты, удаление с подтверждением, каскад при удалении ДЗ, изоляция по `chat_id`, права, недоверенное имя файла, ошибки Telegram API на «мёртвом» `file_id`), работу с БД и конкурентный `get_or_create_chat`, атомарность онбординга и переконфигурации, поведение до `/start` и после полного сброса, права доступа участник/админ в группе, все три режима прав на ДЗ (админ / автор / другой участник, включая старые записи с `NULL`-авторством), авторство и журнал аудита (в том числе то, что удалённая запись оставляет строку истории, а журнал изолирован по `chat_id` и экранирует HTML), безопасный HTML-рендеринг, устаревшие/битые callback-кнопки, edge-cases дат (29 февраля, просроченные быстрые кнопки), outbox-доставку напоминаний (частичный сбой, `RetryAfter`, `Forbidden`) и миграцию group → supergroup. GitHub Actions прогоняет полный CI (лint + типы + тесты + аудит) на каждый pull request, а тесты — перед публикацией Docker-образа.

## ⚠️ Известные ограничения

- Только SQLite — другие БД не поддерживаются и явно отклоняются при старте.
- Троттлинг отправки напоминаний — простая пауза между сообщениями, не полноценный token-bucket.
- Часть межчатовых запросов планировщика (по чатам целиком) не батчится в один SQL-запрос — при очень большом числе чатов возможен рост числа запросов к БД.
